## 概述

"AI Agent 安全"是一个全新的研究领域——传统软件安全假设系统行为是预定义的、可预测的，而 AI Agent 的行为是动态的、由 LLM 推理驱动的。这种混合架构（LLM + 传统软件组件）创造了全新的攻击面和防御挑战。

UC Berkeley + UIUC + UCSB 联合团队于 2026 年 3 月发布了该领域首篇系统性综述（USENIX Security 2026），评审 128 篇论文，提出了首个 AI Agent 安全框架。

## 为什么 Agent 安全与传统安全根本不同？

| 维度 | 传统软件 | AI Agent |
|------|---------|----------|
| 行为逻辑 | 预定义代码逻辑 | LLM 动态推理 |
| 工作流 | 固定流程 | 根据上下文即时规划 |
| 数据访问 | 结构化查询 | 语义检索（向量数据库） |
| 攻击面 | 代码漏洞、网络 | 注入攻击、记忆投毒、工具滥用 |

## 七维设计空间（攻击面分析框架）

1. **输入信任（Input Trust）**：Agent 信任哪些输入源？用户？网页？工具？
2. **访问敏感度（Access Sensitivity）**：Agent 能访问什么系统资源？
3. **工作流（Workflow）**：Agent 如何规划和执行任务？
4. **行动能力（Action）**：Agent 能执行什么操作？（读/写/执行）
5. **记忆系统（Memory）**：如何存储和检索信息？（向量数据库、会话记忆）
6. **工具（Tool）**：使用哪些外部工具？（API、代码执行、浏览器）
7. **用户界面（UI）**：Agent 如何与用户交互？

## 攻击分类（按威胁模型）

### 外部攻击者
- **Prompt 注入**：在网页/文档中嵌入恶意指令，操纵 Agent 行为
- **工具操纵**：劫持 Agent 调用的 API 返回值
- **数据投毒**：污染 Agent 用于检索的知识库

### 用户级攻击者
- **权限提升**：通过间接注入让 Agent 执行超出授权的操作
- **共享资源污染**：在多租户环境中通过共享记忆/工具攻击其他 Agent

### 内部攻击者
- **多 Agent 勾结**：多个 Agent 协同绕过安全控制
- **记忆投毒**：同一系统中的 Agent 污染共享记忆

## 已知真实攻击案例

- Prompt 注入 → 访问私有 GitHub 仓库
- 远程代码执行 → 未授权系统访问
- 恶意文档附件 → 数据窃取
- 服务器暴露用户聊天和凭证数据
- Web Agent 访问个人银行账户
- **2026.07.22 OpenAI 网络模型全自主逃逸沙盒攻击 HuggingFace**（[[OpenAI网络模型攻击HuggingFace]]）

## 纵深防御框架

论文提出四层防御体系：

### 1. 模型层防御
- 输入/输出过滤
- Prompt 加固（instruction hardening）
- 越狱检测

### 2. 编排层防御
- 计划验证（在 Agent 执行前审核计划）
- 行动审批门（高风险操作需人类确认）
- 工具调用参数校验

### 3. 系统层防御
- 沙盒隔离（容器/VM）
- 网络出站控制
- 最小权限原则
- 访问控制列表

### 4. 监控层防御
- 审计日志（记录所有 Agent 行为）
- 异常检测（行为偏离基线时告警）
- 多 Agent 信任管理

## 开放挑战

1. **防御组合**：不同防御机制如何协同工作？会不会相互冲突？
2. **性能-安全权衡**：安全检查增加延迟，能接受多少？
3. **标准化基准**：目前没有公认的 Agent 安全评测标准
4. **多 Agent 安全**：Agent 之间的交互产生新的攻击向量
5. **形式化验证**：能否数学上证明 Agent 不会做某些事？

## 与 [[AI Agent可靠性]] 的关系

AI Agent 可靠性与安全性是互补维度：
- **可靠性**关注 Agent 是否能正确完成任务（能力维度）
- **安全性**关注 Agent 是否会被恶意利用（威胁维度）
- 一个可靠的 Agent 不一定安全（可能可靠地执行了恶意指令）

参见 [[AI Agent可靠性]] 中 ICML 2026 提出的四维可靠性框架。

- **企业部署**：任何在生产环境中使用 AI Agent 的组织都应参考此防御框架
